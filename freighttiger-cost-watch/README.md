# FreightTiger Cost Watch

A smart assistant that spots unjustified shipping cost increases by checking route costs against their own history and peer routes, and validating rises against contextual notes using hybrid retrieval (metadata + TF-IDF) and a deterministic gate.

## Problem & Approach
Shipping costs can creep up for justified reasons (fuel hikes) or unjustified ones. 
To build an assistant that flags these anomalies robustly:
1. **Core metrics**: We track `cost_per_tonne_km` grouped by route and week (starting Mondays).
2. **Dual-Signal Detector**: 
    - **Spike**: A sharp rise (>15%) against the trailing 8-week baseline (strict no-look-ahead).
    - **Drift**: A slow creep where the 26-week moving average increases significantly AND the gap to peer routes widens (catching long-term creep without false-flagging systemic shifts).
3. **Retrieval**: We parse `context_notes.csv` into structured cards. We apply a hard metadata filter (route match & date overlap), then use TF-IDF to rank the applicable notes.
4. **Deterministic Gate**: A matched note ONLY justifies a rise if it explicitly `raises` costs and the observed rise fits within a reasonable tolerance of the stated magnitude.

## Trade-offs & Decisions
- **LLM vs Deterministic Gate**: We deliberately kept the LLM out of the decision loop. The LLM's role is strictly to generate the explanation *after* the deterministic gate evaluates the facts. This guarantees 100% reproducibility and prevents hallucinations.
- **8-Week Baseline**: For routes with less than 8 weeks of history, we use the available trailing weeks.
- **Peer Gap Adjustment**: Certain routes (like Mumbai-Pune) are structurally more expensive than peers. We track the historical peer gap rather than a strict % to prevent perpetual flags on naturally pricier routes.

## How to Run
```bash
pip install -r requirements.txt
make run
```
This will output `outputs/output.csv` and run a format check.

## Cost & Token Logging
Since we used a deterministic template fallback for this run to guarantee execution in constrained environments, the LLM token usage is 0, and cost is $0. If an LLM endpoint is provided, we can wrap the generation function to trace prompt/completion tokens.
